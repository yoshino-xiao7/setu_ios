# AVPlayer 连续供数与时间同步实现

基线：`0b587a8835794bdc1ac426e06e08102c8919dd71`，工作分支 `yukiryou/vlc-music-engine`。正式内核保持 AVPlayer；不合并、不发布。按用户要求安装到连接的 iPhone，由用户进行真机验收。

## 行为

- 已收到的连续字节可直接从内存交付，256 KiB 仅作为落盘块大小；慢写盘不再阻塞这些字节的读取。URLSession 在消费者积压时暂停，消费后恢复。每次下载退出时显式取消传输。
- 文件头确认 FLAC、WAV、MP4、Ogg 或 MPEG 类型；覆盖矛盾的服务器标记。未知类型不默认使用 MP3。完整旧缓存首次命中时核验并修正扩展名，活动文件的租约保持有效。
- Range 返回位置、长度、短响应及越界响应均校验；地址更换不会混合未验证的部分内容。恢复用当前源重新加载一次，只有明确地址失效才强制刷新 URL。
- 用户播放意图与实际播放状态分开；歌词、进度、持久化位置和锁屏使用确认位置。锁屏只在 AVPlayer 实际播放时以速率 1 推进。保留原始媒体时间用于发现被显示上限掩盖的异常。
- 地址解析 20 秒、供数无进展 15 秒、精确定位准备 30 秒、单次操作总预算 60 秒。计时使用可注入的单调时钟。暂停、切歌和停止会使旧任务失效。
- 已开始提交的 seek 若失败，暂停并保留恢复检查点，不继续播放无法确认位置的声音；未提交时保留原播放。
- 快照保存播放器确认的真实时长；旧快照缺少该字段时保留原续播检查点，等待新 item 的真实时长后定位，避免被歌曲资料中的偏短时长截断。
- 有供数且连续缓冲 8 秒，或 30 秒内第三次缓冲达到 1 秒时自动降档。阶梯为 `hires/lossless → exhigh → standard`、`higher → standard`，每曲最多两次；断网、格式错误或拒绝不触发降档。下一曲恢复首选音质，用户可手动切回。UI 显示实际音质。

## 可重复验证

先用本仓库 Xcode workspace 的 `SetuIOSApp` scheme 执行 `build-for-testing`。随后使用生成的 `.xctestrun`：

```sh
python3 scripts/run-continuity-verification.py \
  --xctestrun /tmp/setu-vlc-sim/Build/Products/SetuIOSApp_iphonesimulator27.0-arm64.xctestrun \
  --device <模拟器标识> --source <本地音频文件> --duration <真实时长秒数> \
  --output <证据目录> --mode both --full
```

服务器仅绑定 `127.0.0.1`，默认故意返回 `audio/mpeg`。直连、冷缓存、部分缓存、完整缓存各跑五次；冷缓存第一次额外跑整曲。该矩阵从已解析 URL 开始，度量的是 **AVPlayer 状态就绪时间**，不是点歌到真实出声时间。地址解析和刷新由独立完整控制器测试覆盖。

```sh
python3 scripts/align-continuity-pcm.py <原始音频文件> <证据目录>
```

分析依赖仅用于测试的 numpy、scipy、soundfile。顺序解码参考与 AVPlayer 输出 PCM 做归一化相关匹配：相关性至少 0.8，且与次优位置相差至少 0.05；歧义或捕获不足记为 `inconclusive`。

阈值：目标误差 ≤200 ms、两秒窗口之间的连续性误差 ≤50 ms、解码缓冲尾部与播放器确认位置偏差 ≤500 ms。参考音频前补 0.5 秒数字静音以显式表示解码预卷，输出保留负媒体位置；不剪掉失败片段、不修改歌词偏移。

## 证据边界

- 单测覆盖增量供数、慢盘、格式冲突、Range、取消、独立超时、旧回调、暂停与 seek、降档及 v2 身份。
- PCM tap 位于解码链路，包含预卷和输出缓冲；它验证声音内容定位与软件时间关系，不能证明扬声器、蓝牙或 AirPlay 的实际可听位置。
- 整曲状态连续性、静态 PCM 跳转、真实网络断流、地址重连、降档后的声音定位和完整结束应用后的续播是不同证据，不相互替代。
- 当次日志、原始 PCM、分析结果、输入 SHA-256、构建和源码绑定由外部证据目录保存。未执行或不确定的门槛不得标成修复完成。
